# 回复复测与原文查看

2026-10-06，又测出一个实际错误：模型把账户类型 **ESAVINGS ACCOUNT** 当作 `bank_holder`，以低置信度写入事实表。它未用于自动放行，但字段本身错误。新增校验拒绝账户类型/字段标签作为持有人；同时接受有原文支持、年份在前的 `YYYY/MM/DD` 日期，保持低置信度标记，不猜测有歧义的日/月顺序。

此前“通过”只检查字段约束和阻塞状态。实际客户回复会重复三次要求合并流水，或者上传材料后仍只问基础背景。当前模型输出 `Proposal` JSON 和 `read_evidence` 工具调用；中文客户回复由 `rules.reply_for()` 生成。两者都已导出，不能把模板回复当作模型原话。

本轮使用同一组公开扫描图片/PDF，未修改材料和原有字段预期。[冻结配置](../../datasets/public-replies-stress.json)新增四项回复检查：确认收到文件、解释材料阻塞、合并重复补页要求、最多三个行动项。它们是机械检查，不代表顾问交互质量合格。全部案件仍为 WAIT_USER/NEEDS_HUMAN，没有完整交付或人工批准。

修复后，回复先确认当前文件数量，优先解释阅读/页面问题，同类补页要求只出现一次。**仍有三轮模型提案被拒绝**：不完整流水的最低余额、引用不足的流水日期、在原文中找不到的家属信息。来源校验阻止了这些字段进入有效判断；不能称为模型已稳定提取正确。每种场景在最终版本只跑一次。

```text
1. 05-BOC-Warwick-partially-redacted.png 的部分内容无法可靠读取。请上传清晰完整版本，或请顾问对照原件确认。
2. 请为 05-BOC-Warwick-partially-redacted.png 提供完整译文及译者声明、日期、签名和联系方式。
3. 请提供与身份证件一致的申请人姓名。
```
