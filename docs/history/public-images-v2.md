# 公开扫描图片：第二轮验证

2026-10-06，使用 `deepseek-flash` 完成 **12 次案件运行、24 次真实请求**。八种场景首轮 **4/8** 满足冻结检查；修复后针对四个失败场景各复测一次，**4/4** 满足检查。跨版本共 8/12，不能作为最终版本的稳定通过率。

本轮附件全部来自大学公开脱敏扫描件：5 张原页 PNG，以及 Warwick 原 PDF。没有使用自制申请人附件。新增 [Warwick 中国银行存款证明](https://warwick.ac.uk/study/international/visa/applying-for-a-visa/visas-for-studying/student-visa/certofdeposit.pdf)，保留部分遮盖的姓名、银行印章、旧日期及批注。来源公开不等于原始客户真实性已核实。[图片与来源](../public-images.md)列出本地文件。

## 修复与限制

- `pagination_problems()` 同时用于 PDF 和图片；有明确缺页的材料不能贡献整段最低余额。无页码的缺页仍无法可靠识别。
- 不同图片文件即使页码连续，也不自动当作同一文件。顾问需确认归属，或客户上传按顺序合成的完整 PDF。三张齐全图片仍可能需要人工处理，这是保守边界。
- 工作摘录标明原文长度和是否截断。完整页超过剩余容量时，工具明确返回未读取；案件记录持久的阅读问题，顾问核对全文前不能放行。12,000 字符上限未提高。
- 上传页默认空白案件。只有主动选择合成演示才注入虚构背景；人工确认记录也不再一律声称材料为合成文件。

剩余八次整套第二遍运行没有执行：请求额度用于四次针对性复测，已达到 **24/24**。四个修复场景各有一次真实复测，不能据此宣称随机波动已消除。这是串行鲁棒性验证，没有测生产并发吞吐量。

复现需要按来源说明准备同字节输入。新实验使用独立输出目录，仍受冻结的 24 次请求限制：

```powershell
uv run python scripts/bad_case_suite.py run --manifest datasets/public-images-stress.json --output output/public-images-next --count 4
```

同目录继续执行会跳过已有记录，包括失败结果。脚本若发现历史失败会返回非零退出码，即使本次复测全部通过；应结合分阶段记录判断。手动体验时，每种组合另建空白案件，先输入申请路线及日期，再拖入对应图片。
